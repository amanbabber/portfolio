02 · Approach
How I work
A

I diagnose before I scope

The contract dashboard rebuild started with confirming, alongside engineering, exactly why the old page was slow — not with a redesign brief. Root cause first, spec second.

B

I ship code, not just specs

I work directly in the codebase via Cursor and have shipped code to production myself. I can read a pull request, not just a Jira ticket.

C

Eval methodology over demo confidence

For AI features, I build the golden dataset and set the threshold — the boring, precise work that decides whether a feature is trustworthy in production.

D

Solo, end to end, on purpose

As the only PM across two of three squads, I own diagnosis, scope, spec, sprint management, and QA on every feature I ship — there's no one else to hand it off to.
